# vibelang/x64.py

## What it is
A hand-written x86-64 machine code encoder: each method appends one instruction's bytes to a buffer. No external assembler is used.

## How to navigate it
- Top: register numbers (`RAX`..`R15`), condition codes `CC`, `SIGNED_CC`/`UNSIGNED_CC`/`INVERT_CC`, ALU opcode tables.
- `Mem` and `rip()`: memory operands (`[base+index*scale+disp]` or `[rip+label]`).
- `Asm`: the buffer, `labels`, and `fixups` (4-byte holes filled in later). Encoding primitives `_rex`, `_modrm_m`, `_op_rm` come first, then groups: moves, arithmetic, control flow, and SSE (scalar float and 128-bit SIMD vector instructions), plus atomics (`lock_cmpxchg`, `lock_xadd`).

## What it interacts with
No local imports (only `struct`). codegen.py drives `Asm` and resolves its fixups; regalloc.py imports the register constants.

## Why it exists
Lets the native backend produce every byte of a VIBE binary itself.

## Helpful notes
- Jumps, calls and rip-relative operands leave a 4-byte fixup (`"rel"` or `"rip"`); codegen.py's `link` patches them.
- `mov_ri(r, 0)` emits `xor r, r`, which changes flags.
- `_modrm_m` has a leftover `if idx is not None or True:` that is always true.
